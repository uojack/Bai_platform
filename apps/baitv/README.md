# BaiTV

独立的局域网电视快速恢复入口，运行于现有BaiPlay本机；不是另一套EOS开发线。

## 使用

- 本机：`http://127.0.0.1/`；短域名可用管理员命令安装：`sudo .venv/bin/python apps/baitv/install_macos.py --hosts`。
- 手机：同一局域网访问 `http://baitv.local/`。Bonjour名称是否能跨网段访问取决于网络；也可使用本机局域网IP。
- 手机第一次输入本机页面「播放依据与连接说明」中的8位连接码，登录cookie为30天；本机私有配置为 `private/baitv/auth.json`。不要提交或分享此文件。
- 选择一台、全景三台或四台，逐台指定四种可用直播节目之一，点击「恢复指定画面」。当前支持六页轮播与全景左/中/右；不接受任意外部网址或未知设备。
- 「停播后自动恢复」只对仍指向明确托管节目的停止状态有效；其他URI及暂停不接管。DLNA不能独立证明电视当前物理输入，现场输入切换仍需核对。
- 预览图片来自本机渲染源；“持续取流”来自相应电视实际分片请求，不等于已核实屏幕像素或冷启动。

## 运行与停止

`.venv/bin/python apps/baitv/install_macos.py` 安装两个本用户登录服务：Web入口与Bonjour别名；登录会话中保持运行，停止用同一脚本 `--stop`，不清理数据。不改本机原主机名、不改路由器、不启用外网映射。旧系统级六项BaiPlay服务保留。

Web进程只写SQLite命令，不直接控制电视。唯一BaiPlay supervisor消费命令、持有文件锁、核UDN、检查本机HLS新鲜度和媒体HTTP，再推送。重启期间已开始但未知的请求不自动重放；重复同编号同内容返回原回执。仅对既有现场明确配置工作，配置和运行库不入Git。

源码：`bridge.py`、`server.py`、`web/`；集成点 `tools/huawei_panorama_autostart.py`。运行状态与命令位于 `runtime/baitv.sqlite`。回滚先停BaiTV两个登录服务，保留命令/偏好/连接信息，按原备份恢复唯一监护脚本并由服务所有者重载；不要同时启两个监护。

## Pulse V1.5

继承六页与三屏视觉，兼容已核验的vision.result 1.5。只读字段白名单排除人脸属性、图像及转录；展示临近摄像头人数估计与dBFS、整体吞吐/耗时/GPU显存、各子算法耗时及19路当前通道数据。声学页补充三支研发麦克风和八通道阵列的连接/年龄/事件密度，保留24维及各参数窗口/历史沿用限制；未校准与未实现不补值。

源数据2秒采集，网络健康15秒；HTTP请求有界，原数据失败后不冒充实时。渲染到电视另有编码/网络缓冲延迟。每个来源和参数状态独立，不把服务器连接成功当所有模型新鲜。

## 验证

`.venv/bin/python -m unittest discover -s tests -v` 使用临时库和合成设备。流渲染故障检查：`node --test tests/test_stream_recovery.cjs`。实际设备恢复与分片观察属于经用户授权的现场操作，不在单元测试中执行。手机尺寸仅浏览器模拟，实际手机及电视物理断电仍需现场验收。
